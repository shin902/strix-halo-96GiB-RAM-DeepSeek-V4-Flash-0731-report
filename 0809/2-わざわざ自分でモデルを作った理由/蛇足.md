# 蛇足
REAPする演算をS、量子化する演算をQにすると、Qがエキスパートごとに完全独立なら
```
S(Q(W)) = Q(S(W))
```
は多分成り立つ  
ただ、実際は`REAP checkpoint → quantize`と`quantize → prune`が同じになる保証はないそうで  
てかそれ以前に、上の問題は下のREAP GGUFがMXFP4量子化で公開されてたこと自体が問題な気はする


だから、FullのDS4 Flashからめっちゃ圧縮するためにQ2の非対称量子化をしてたけど、それプラスREAPの効果もあるんだから、もう少し削る量を少なくして（一部をq2からq4に戻したりして）、数ギガ全体で多くなってもいいから精度を向上するのはアリなんじゃない？とも言ってた。
> 実際、Fullモデル側ではこの発想は既にかなり効いています。最近のGGUF検証では、後半expert layerをnative MXFP4のまま残して、前半だけIQ3にすることで、サイズとKLDの良いPareto点を作っています。たとえば全expert IQ3が106.1 GiBなのに対し、後段21 expert layersをMXFP4で残す版が124.8 GiBで、KLDが0.0775→0.0539まで改善しています。 https://huggingface.co/bullerwins/DeepSeek-V4-Flash-GGUF/blob/main/README.md?utm_source=chatgpt.com
> また別の実験では、Q2 baseline 80.76 GiBからわずか6層だけQ4に戻して90.89 GiBにすると、NLLが約8%改善しています。どの6層をQ4にするかでも差が出ています。 https://huggingface.co/ivanfioravanti/deepseek-v4-gguf/blob/main/README.md?utm_source=chatgpt.com
> そしてREAP側でも一例だけ近いものがあって、K180でgate/upをNVFP4のまま、downだけQ2_K、attention/shared/outputをQ8にするmixed quantが公開されています。「gate/upをIQ2_XXSまで落とすよりprecisionを残したい」という思想そのものです。 https://huggingface.co/sleepyeldrazi/DeepSeek-v4-Flash-REAP-K180-NVFP4/blob/main/README.md?utm_source=chatgpt.com
> K160ではさらに、W4A16でattention/indexer/compressor/shared expertをBF16のまま保持した約97GB版も実際に作られています。 https://huggingface.co/Israeli-AI/DeepSeek-v4-flash-180b-W4A16-VOLTA-Ampere/blob/main/README.md?utm_source=chatgpt.com
> なので、
>> REAPモデルに対して、固定容量60GBという条件でprecision allocationを最適化する

> という探索は、少なくとも今見つかる公開例ではかなり手薄です。

> 最初は安全な
> ```
> Full DS4 Q2 → K160 prune ≈56GB
> ```
> を作って動作確認。

> それをbaselineにして、残り4〜8GBを使って、
> ```
> K160-Q2                  56GB
> K160-Q2 + selected Q3/Q4 60GB
> K160 + precision-aware   60GB
> ```
> を比較する。

> これなら「K160が動くか」という生存確認と、「60GBをどう使えば一番品質が残るか」という研究を分離できます。

> ### 3経路を並べると分かりやすい
> 
> ① heath0xFF方式
> ```
> Full
> → REAP checkpoint
> → GGUF
> → quantize
> ```
> ループ報告あり。
> 
> ② 安全寄りの既存方式
> ```
> Full
> → Q2 GGUF
> → REAP K160
> ```
> 量子化済みexpertをbyte-copy。
> 
> ただしおっしゃる通り、Full 256 expertsを80GBに押し込むためのQ2を先に掛けてしまっている。
> 
> K160化後は56GB程度まで減るのに、既に2bitに潰した情報は戻ってこない。
> 
> ③ 本当に試したい方式
> ```
> Full
> → MXFP4/Q4などの比較的高精度な正常GGUF
> → GGUF上でREAP K160
> → K160 ~95〜103GB
> → 重要度を見ながら60GBまで量子化
> ```
